# 寻径教育 PathFinder · LearnBuddy

> 面向高校的**学业—就业双轨智能导航平台**。
> 依据手写技术文档与实现流程逐步构建，可优化处已做补强。
> **无网络、无 API Key 也能完整演示全部链路。**

**当前版本 v7.27**（2026-09-24）· 10 个页面 · 26 个业务模块 · 后端仅 8 个 Python 依赖 · 前端零构建 ·
冒烟测试 **71/71**。

---

## 一、这个项目在解决什么

高校里「一个学生该往哪走」这件事，信息散落在四个地方：成绩单、兴趣自述、科研/就业倾向、企业侧的岗位与项目资源。辅导员和教师靠经验拼接，学生自己看不到全局。

PathFinder 把这些拼起来，做成一条能跑通的闭环：

```
画像（你是谁） → 匹配（去哪） → 答疑（卡住时问谁） → 资源（拿到什么练） → 作业（练得怎么样）
   ↑                                                                        │
   └──────────────────────── 结果回写进画像 ─────────────────────────────────┘
```

需要注意的一点：平台产出的**分层结论只用来决定「推荐内容的深度」与「任务难度」**，不用于分班、不构成准入门槛。这条口径写在代码里，也写在每一个展示分层的界面上（界面统一附带 `PF.caveat` 提示）。

## 二、三分钟跑起来

```bash
# 1. 依赖（Python 3.10+，开发环境实测 3.13 / 3.14）
pip install -r requirements.txt

# 2. 配置（可选。不配任何东西也能跑 —— 默认就是规则版）
cp .env.example .env

# 3. 启动
python backend/app.py
#   → http://127.0.0.1:8000
```

> **开发时建议加 `--reload`**：`python backend/app.py --reload`。
> 默认不带热重载，改了后端 `.py` 而不重启，页面会一直在跑旧逻辑——而且**一切看起来都正常**，
> 最难排查。一个直观的确认信号：`POST /api/selfcheck` 返回的项数会随代码变化（当前教师 14 项 / 学生 13 项）。

首次启动会自动建库、建表、灌入种子数据（3 位教师 / 72 名学生 / 6 个行政班 / **7 个团队**（科研课题组、横向项目、竞赛团队、实习实践四种类型）/ **9 条资源**（团队招募、竞赛、校企合作项目、实习内推）/ 6 份预置材料 / 3 份作业 + 7 份学生提交）。预置材料会当场走一遍「解析 → 抽知识点 → 建索引」，所以一开机检索就不是空的。

**浏览器要求**：无。原生 HTML/CSS/JS，零构建、零前端框架、零 npm。

### 切换到真实模型

只改 `.env`，**代码一行不动**：

```ini
LLM_MODE=api
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=sk-...
LLM_MODEL=gpt-4o-mini
```

改完重启即可。任何一个模型调用失败，都会自动回落到规则版，界面上的徽标从「AI 生成」变成「规则生成」——功能不会中断。

### 部署到 Vercel（线上演示）

仓库里已经带好了部署适配层（`api/index.py` + `vercel.json`），把仓库导入 Vercel 即可：

1. 仓库推到 GitHub（`api/index.py` 是 Serverless 入口，`vercel.json` 把全部路由交给 FastAPI）；
2. Vercel 控制台 **Add New → Project**，导入该 GitHub 仓库，**不需要改任何设置**，直接 Deploy；
3. 部署完成后拿到 `https://xxx.vercel.app` 链接，账号与本地一致（`teacher` / `stu01`，密码 `123456`）。

**平台差异（无服务器架构决定的，提前说明）**：

* Vercel 函数的代码目录只读，SQLite 自动落到 `/tmp`（`api/index.py` 里通过 `DATA_DIR` 环境变量切换，后端代码零改动）；
* **登录会话是自己签名的 token**（`v2.<用户id>.<过期时间>.<HMAC 签名>`，见 `db.make_session_token`），
  不依赖数据库，因此**跨实例、跨冷启动都不会掉线**；正式部署可在环境变量里换一个自己的 `SECRET_KEY`；
* 实例回收后 `/tmp` 清空，下次冷启动由 lifespan 自动重建种子数据——**线上永远是干净的初始演示数据**；
* 上传的素材、聊天记录、作业提交在实例回收后不保留（演示口径，不是数据丢失 bug）；
* 从旧版本升级上来时，浏览器里的旧格式 cookie 会失效，**重新登录一次**即可；
* 若在 Vercel 环境变量里配置了 `LLM_*`，线上同样切真实模型；不配就是规则版，**零 Key 也能跑**。

需要数据持久化的正式部署，建议换长驻进程平台（Render / Railway / Fly.io，`python backend/app.py` 直接跑），或把 SQLite 换成 Turso / Postgres。

## 四、核心设计一：双引擎 + 规则兜底

这是整个项目的地基，也是唯一一条「不许破例」的纪律：

```python
data, engine = llm.chat_json(messages, schema_hint=..., mock=rule_result)
# engine == "llm"  → 界面徽标「AI 生成」
# engine == "rule" → 界面徽标「规则生成」
```

要点：

1. **规则版不是占位符**。它用真实算法（分层规则、BM25 检索、要点匹配计分）算出**结构完全一致**的结果，所以断网演示时界面不会空着。
2. **`mock=` 是必填参数**。任何一个模型调用都必须给出规则兜底，否则代码层面就过不去。
3. **失败即降级，不抛网络细节**。统一 2 次重试 → 收敛为 `LLMError` → 回落规则版。JSON 解析不出来等同于调用失败。
4. **合并补齐**。模型返回缺字段时，用规则版对应字段补上，不让半成品流进业务层。
5. **engine 一路透传到前端**。所有模型能力的结果里都带 `engine`，前端 `PF.engineBadge()` 常显，用户永远知道这条结论是怎么来的。

## 五、核心设计二：自研同构，不用 LangChain

技术上刻意**不引入 LangChain**——它的抽象层会掩盖掉「模型失败时怎么办」这个本项目的核心命题。但保留它的分层思想，用约 400 行自研代码同构等价：

| LangChain 概念 | 本项目实现 | 位置 |
|---|---|---|
| `ChatOpenAI` | 统一 HTTP 出口（含超时/重试/JSON 抽取） | `backend/llm.py` |
| `with_fallbacks` | `mock=` 参数 + 逐级降级 | `backend/llm.py` |
| `ChatPromptTemplate` | `tutor.system_prompt()` 按画像拼装 | `services/tutor.py` |
| `JsonOutputParser` | `llm._extract_json()`（容忍 ```json 包裹与前后噪声） | `backend/llm.py` |
| `EnsembleRetriever` | `retriever.hybrid_search()` | `services/retriever.py` |
| `RunnableWithMessageHistory` | `db.recent_chat()` 取最近 4 轮 | `backend/db.py` |

自研反而换来了两个 LangChain 给不了的东西：**降级路径是类型系统逼出来的**（不给 `mock` 就调用不了），以及**零框架依赖**（`requirements.txt` 只有 8 个包：fastapi / uvicorn / pydantic / python-multipart / httpx / python-dotenv / pypdf / python-pptx）。

### 检索是怎么做的

```
                ┌── BM25（SQLite FTS5 + trigram 分词器）──┐
query ──────────┤                                          ├── RRF 融合(k=60) ── 重排 ── top-N
                └── 向量余弦（本地 3-gram md5 哈希 1024 维）─┘
```

- **FTS5 不可用时自动降级为 LIKE**（`db.FTS_OK` 标记），启动日志会明确打印。
- **没有 embedding API 时的向量兜底**：本地字符 3-gram + md5 哈希 → 1024 维 → L2 归一化。它不是语义向量，但足够在演示中体现「双路召回 + RRF 融合」的完整链路。
- 检索到的切片带 `via` 字段（`bm25` / `vec` / `bm25+vec`），界面上能看到每条命中是被哪一路召回的。

### 检索的可见范围：用户数据隔离

检索不是全库扫的，**每个用户只能看到自己有权看到的部分**（纯数据权限，与"分层"无关）：

| 角色 | 可见范围 |
|---|---|
| 学生 | 自己上传的资料 + **已导入**的教师公用资料 |
| 教师 | 自己上传的资料 + 全部教师公用资料（公用池本就是教师共建的） |

- 同学之间互不可见：成绩单、简历是私人材料，绝不能出现在别人的答疑引用里。
- 「导入」是显式授权：学生在「我的资料库 → 资料列表」的**教师共享资料**区点「导入数据库」，
  之后这份资料才进入自己的检索范围；「移除导入」只删引用记录，不动老师那边。
- 实现是引用表 `material_imports(user_id, material_id)`，不复制正文；删除资料时级联清理。
- 唯一入口是 `rag.search_scope()`（SQL 子句）+ `rag.visible_material_ids()`（向量路内存过滤），
  五种 RAG 架构、答疑、备课、Agent 工具、资料检索、课程下拉全部走它；传 `owner_id=0`
  （旧调用 / 自检）保持全库行为，向后兼容。
- 种子数据为演示学生**预导入**了全部教师公用课件（`seeds.seed_imports()`），避免隔离后检索为空；
  新注册的真实用户则需要自己去「教师共享」区导入。

### 驾驶舱的班级切换与分布方框

* **右上角「班级」按钮**列出该教师的任教班级（来自 `teacher_classes`），外加「全部任教班级」；
  选择写入 `localStorage`，下次进驾驶舱还是这个班。越权的班号会自动退回主班。
* **分布用方框呈现**：主标签分布、学业层次分布各一排方框，**人多的那一类占两列**（`.tile--lead`，
  字号更大、描边取该类别的主题色），方格内直接印交叉构成（如「A 层 6 · B 层 1」），下面一句话
  说明构成并给出教学建议，例如「班级学生以 学业型 为主：7 人（58%），其中 A 层 6 人、B 层 1 人。
  **建议**：本班以学业型为主，建议多给科研方面的帮助……本班同学兴趣相对集中在 「机器学习」 3 人、
  「LLM」 3 人，建议围绕这些方向组织团队、布置拓展任务。」
* 兴趣分析句的数据来自 `overview` 返回的 `interest_dist`（方向 + 人数），热门方向占比 ≥ 35% 时
  措辞用「兴趣明显集中在」，否则「兴趣相对集中在」。
* 两类人数相同时不放大任何一方，改用「势均力敌」的文案并给「两类资源并重」的建议（CS2302 就是这种情形）。
* 交叉数据来自 `stats.track_level`（主标签 → 层次），前端再转置一份层次 → 主标签。

### 课件链路：生成 → 入库 → 共享 → 预览 → 打开

备课这条线是完整闭环，不只是「下载一个文件」：

1. **生成**（`services/office.py`）：`build_pptx()` 双路径 —— 默认走 `python-pptx` 的富排版（封面 + 内容卡片 + 页脚，风格取自根目录 `ppt制作提示词.txt`），异常或缺少依赖时自动回退零依赖的手写 OOXML；教案同理生成 `.docx`。
2. **入库**（`services/mylibrary.save_courseware()`）：`.pptx` 落进 `data/uploads/{uid}/`，按页标题抽知识点写进知识库，`material_id` 非空时覆盖同条，`artifacts.material_id` 把产物与资料关联起来。
3. **可见性**：`materials.shared` 默认 1；备课产物 `shared=0` = 教师私有，**不进学生的「教师共享」池**（`shared_materials()` / `import_material()` 同步过滤）。
4. **预览**（`GET /api/materials/{id}/preview`，v7.19）：用 python-pptx 把 `.pptx` 读回「文字骨架」（按 shape 纵坐标排序取标题、剔页脚品牌行、把「讲法提示：」回收成备注），前端弹窗翻页（← → 键、圆点跳页），非 pptx 返回 415。
5. **打开**（`GET /api/materials/{id}/download`）：本人或已导入才可下载，`material_file()` 防目录穿越。

## 十、诚实的局限

写出来比藏起来好。

1. **层次评定是规则算出来的，不是模型评的**。`stratify.py` 按成绩 + 科研/就业倾向得分落格。它可解释、可复现，但不要当成教育学意义上的科学测评。
2. **向量检索默认不是语义向量**。没有 `EMBED_MODEL` 可用时，走的是字符 3-gram 哈希。想看真正的语义召回，请配 `LLM_MODE=api`。
3. **图片解析依赖视觉模型**。未配置 `LLM_VISION_MODEL` 时，图片素材会被标记为「需人工批改」，并且**不生成**知识点——这是有意的降级，不是 bug。
4. **批改建议分不是评分权威**。规则引擎判断不了对错，走的是「完成度基础分 + 篇幅 + 要点覆盖 + 结构」的加分口径（`teaching.rule_grade`），正常完成的作业落在 70 上下；要点命中用的是归一化后的等价写法匹配，仍会有漏判。教师定分才是最终结果，界面上一贯以「建议分」措辞。
5. **鉴权是演示级的**。`pwd_hash` 用的是项目内实现的哈希，会话是 SQLite 里的一行记录。上生产要换成成熟的认证方案。
6. **PPT 是内容大纲，不是设计稿**。默认 `python-pptx` 排版（缺依赖时回退手写 OOXML），样式朴素但**真能打开、真能编辑**，不装任何 Office 组件也能生成。
7. **课件预览只还原文字骨架**。`GET /api/materials/{id}/preview` 把 `.pptx` 读回标题与要点（含备注），**不还原版式、图片与动画**；要真正放映请点「打开」下载原文件，非 pptx 直接返回 415。
8. **演示会污染开发库**。每次实操演示都会新增资料 / 产物 / 作业 / 团队，并把 `resource_applications` 从 pending 改成已批复。正式路演前建议用一份干净库（`DATA_DIR` 指向新目录即可）。

### 动效层（`frontend/js/common.js`）

四条自我约束（改之前先读）：

1. **只动 `opacity` 与 `transform`**，不碰 `width/height/margin` 等布局属性；
2. 时长封顶 400ms，缓动一律快起慢收；
3. 命中 `prefers-reduced-motion: reduce` 时**整个 `MutationObserver` 根本不安装**；
4. 元素**默认可见**，动画只是 JS 参与时额外加的入场效果 —— JS 挂掉、浏览器不支持、用户开了减少动效，三种情况页面都完整可用。

对外只有两个入口：`PF.reveal(scope)`（手动触发）与自动观察 `document.body` 的子树变化。数字滚动只改文本节点、进度条/分数环走两次 `requestAnimationFrame`（不用 `void el.offsetWidth` 强制同步布局），可见性判定「先读后写」，避免 N 次同步布局。

### 无障碍

- `PF.shell()` 顶部注入 `.skip-link`「跳到主要内容」，`<main id="pf-main" tabindex="-1">` 可聚焦
- 导航当前项带 `aria-current="page"`；移动端抽屉按钮带 `aria-expanded` / `aria-controls`
- 标签条按 ARIA tabs 模式实现：`←/→/Home/End` 移动并激活，roving `tabindex`
- `PF.modal()` 有焦点陷阱与焦点归还（关闭后焦点回到触发元素），带 `role="dialog"` / `aria-modal` / `aria-label`
- 移动端触控目标一律补到 32px 以上（`.btn` 38px / `.input` 40px / `.nav-item` 11px 内边距）

### 零新增依赖

仍然是原来那几个 Python 依赖（8 个），**零 npm、零前端构建、零网络字体**。所有动效都是原生 CSS + 原生 JS；无法访问外网时视觉表现完全一致。

### 学生画像雷达图（`PF.radar`，v2.5 引入）

「能力画像」原来是一排横向进度条，五项能力的强弱对比要来回扫视才能读出来。改成**雷达图**后，一眼就能看出这个学生的形状偏哪边（尖角是优势、凹口是短板）。

| 位置 | 变化 |
|---|---|
| `/student` · 能力画像 | 五维进度条 → 雷达图；下方补「优势 / 待提升」两个结论 chip |
| `/teacher` · 学生画像弹窗 | 同上（半径略小以适配弹窗） |
| `/profile` · 五维能力 | 同上（紧凑尺寸） |

**实现方式（零依赖）**：`PF.radar(items, opts)` 在 `common.js` 里手算极坐标画 SVG，不引入任何图表库 —— 依赖清单仍然是 8 个 Python 包，前端依旧零 npm、零构建。

- **几何**：`n` 个轴均分 360°，从正上方起算；4 层同心多边形网格，最外层填 `surface-2` 做底；顶点半径 `R × value / max`（`max` 默认 5，下限 0.02 防止全 0 时退化成一个点）
- **可读性**：轴标签带数值（`专业基础 4.8`），按 `cos` 值自动切 `start / middle / end` 对齐、上下极位额外做 ±4~8px 偏移，实测五个标签全部落在 viewBox 内，不越框
- **交互**：顶点 `<title>` 提供原生 tooltip；hover 顶点放大并加深描边；数据面 `radar-in` 关键帧从 0.42 倍缩放淡入（380ms）
- **主题**：描边、网格、文字全部走 CSS 变量，深色主题自动反相
- **无障碍**：`role="img"` + `aria-label`，`prefers-reduced-motion` 下关闭进场动画

顺带在 `common.js` 增加了 `PF.radarTips()`：按分值排序给出「优势 / 待提升」，让图旁边有一个可以直接读走的结论。

## 十三、对话智能体：RAG 路由 · Agent 工具 · 会话管理

### 13.1 为什么不能只用混合检索

混合检索（BM25 + 向量 + RRF）只擅长"知识点的文字解释"这一类问题。真实对话里还有：
问 A 和 B 什么关系（该走图结构）、结合我的情况给个计划（要先拆任务再调多个数据源）、
"那个为什么不行"（口语指代，首查大概率落空，得先改写再查）、"课件里那张图"（必须把图片一起召回）。
**一种架构解决不了所有问题，所以先路由、再执行。**

`services/ragroute.py` 里五种策略全部有真实实现（不依赖网络）：

| 策略 | 什么时候用 | 它怎么做 |
|---|---|---|
| `hybrid` 混合式 | 知识点的文字解释（默认兜底） | BM25 + 向量双路召回，RRF 融合 |
| `graph` 图谱式 | 问关系 / 关联 / 前置 / 知识链路 | 以知识点为节点建子图，先查子图再看证据 |
| `agentic` 智能体式 | 复合任务：结合我的情况、要计划、要对比 | 先规划 → 调多个工具 → 聚合推理 |
| `corrective` 纠错型 | 口语、指代、含糊 | 先给检索质量打分，不合格就改写问题再查一次 |
| `multimodal` 多模态 | 问图表 / 图片 / 扫描件 / 版面 | 文本块与图片素材统一召回，回答同时引用两者 |

- **路由有两条引擎**：规则路由（默认，断网可用）+ `route_llm()`（接口已留好，让模型五选一并给理由，规则版作 mock 兜底）。
- **路由结果对用户可见**：每条回答下方有 RAG 卡片，标出这次用了哪种、为什么；
  输入框旁的下拉可以手动指定策略（演示时用来对比同一问题在不同架构下的差别）。
- `execute()` 返回的 `hits` 与 `retriever.hybrid_search` **同构**，所以下游答疑与引用卡一行没改。

### 13.2 它不只是聊天：Agent 工具层

`services/agenttools.py` 把对话之外的动作收敛成工具注册表（`GET /api/agent/tools` 出清单，
`POST /api/agent/tools/{id}/run` 执行），加工具只需往 `TOOLS` 里 append，路由不用动：

| 工具 | 做完得到什么 |
|---|---|
| `upload_material` 上传资料 | 文本作为正式材料入库：解析 → 抽知识点 → 建索引，下一轮提问就能引用它 |
| `generate_material` 生成资料 | 基于检索证据 + 画像生成复习提纲 / 错题卡 / 学习小结 / 教案要点 / 练习题 |

**可溯源是硬要求**：生成时先检索真实材料当依据，正文标注引用了哪几份（`refs`），
结果可一键存进资料库并进入检索索引。教师侧同样可用，且"查事实用班里真实数据、讲内容用上传资料"两者分开展示。

### 13.3 会话管理

- 左栏上半是「全部会话」（按时间倒序，点一条回到那次），下半是「本次对话」的每一轮问答；
- 「新开对话」起一条全新的线，旧的全都留在列表里；「清空」只清当前这一次；
- 数据层：`chat_messages.session_id` + `db.chat_sessions()` 按 `session_id` 聚合出轮次与首条提问；
- 学生侧 `/api/tutor/*` 与教师侧 `/api/teacher/copilot/*` 共用同一套接口形状（sessions / new / history / clear）。

**两个页面的对话区是同一个壳**（`.qa-shell`）：左右栏各自滚动，**只呈现当前这一轮**，历史轮次收进左侧历史 dock，
避免长对话把页面撑成一堵墙。智能体自称「助教小寻」。

学生端还有一个**本轮范围下拉**（`#c-scope`）：`course:<课程名>` 把检索限定在某门课，`career` 切成事业取向口径 ——
**只覆盖本轮的回答视角，不写回画像**，所以学生切一次不会把自己的定位改掉。

### 13.4 演示素材与问答集

测试师生两个功能用到的图文资料与问答，统一放在 `samples/`（`samples/README.md` 有对照表）：

```
samples/答疑问答集-学生.md   26 条，7 个场景（概念辨析 / 作业卡点 / 路径规划 / 多模态图谱纠错 / 边界情况……）
samples/答疑问答集-教师.md   16 条，覆盖备课 / 讲解 / 查学生 / 批改 / 边界
samples/RAG路由测试题.md     判据一览 + 五种架构各一组问题 + 手动指定策略的演示说明
samples/*.md / *.png        ① 解析与 ② 抽取用的素材
```

每条问答都写了「期望」与「依据」，既能照着念，也能直接当验收标准。

### 13.5 综合生成：回答不是检索片段的拼接

检索只负责"把可能有用的片段找出来"，回答还要再过一遍脑子。`services/synth.py` 就是这一层：

```
证据归集 → 要点归并 → 结合学情组织推理 → 补易错提醒 → 标出处与下一步
```

- **模型综合**：`synth.compose()` 把证据 + 画像 + 层次交给模型，要求按
  「直接结论 / 怎么推出来的 / 容易混淆的地方 / 下一步」四段输出，**禁止照抄资料原文**；
  推断句与资料句分开，界面上区分"资料里的"和"它推的"。
- **规则综合（断网演示）**：按 `REASON_RULES`（8 类问题各一套讲法）+ `INFER_RULES`
  （把两条证据连起来的那一句判断）改写成一条讲得通的推理 —— 不是片段罗列。
  规则表即数据，加一种讲法只 append，不动流程。
- **前端可见**：答案下方是可折叠的「看它怎么想出来的」，列出五步与用到的证据原文；
  徽标照常显示「AI 生成 / 规则生成」。
- 学生侧 `/api/tutor/ask` 与教师侧 `/api/teacher/copilot/ask` 都返回 `synth` 视图，结构一致。

## 十五、数据口径与工程纪律（改代码前先读）

### 数据口径

| 字段 / 概念 | 口径 |
|---|---|
| `users.class_id` | **行政班**：班级总览、匹配打分范围用它 |
| `users.class_name` | **教学班**：作业分发用它 |
| `student_profiles.gpa` | **百分制**（不是 4.0 制），A/B 分档 85 / 75 |
| 层次 A / B / C | 只决定**推荐内容深度与任务难度**，严禁出现分班措辞，每个展示分层的界面都挂 `PF.caveat` |
| 团队类型 | 科研课题组 / 横向项目 / 竞赛团队 / 实习实践四类，两端共用 `GROUP_KINDS`；**类型只做展示与筛选，不参与匹配打分** |
| `materials.shared` | 默认 1 = 教师公用；备课产物 `shared=0` = 教师私有，不进学生「教师共享」池 |

### 改代码前的六条

1. **双引擎不许破例**：任何模型调用都要传 `mock=` 规则兜底，返回 `(结果, engine)`；`engine` 一路透传到前端徽标。
2. **检索 ≠ 回答**：`retriever` / `ragroute` 只负责找证据，答疑与备课的答案必须过 `synth.compose()` 组织成「结论 + 推理 + 易错提醒 + 出处」。
3. **规则表即数据**：`parsekit` / `kprules` / `interaction` / `ragroute` / `agenttools.TOOLS` / `synth` / `manual` 里的规则表**只 append 不重排** —— 说明书与测试用例都从这些表生成，改顺序等于改文档。
4. **分层措辞**：任何新增文案都不得出现「分班 / 快慢班 / 门槛」这类说法。
5. **前端改 CSS 或公共 JS 必须升版本号**（当前 `style.css?v=34`、`common.js?v=20`，全量替换），否则浏览器缓存会让改动"看起来没生效"。
6. **`PF.tabs` 有渲染缓存**：切回已渲染的标签不会重跑 `render`。跨标签「选中某一条」这类意图要用模块级 `PENDING_*` 变量传递，且**不要在 `render` 里就地清空**（`tabs.go()` + `tabs.reload()` 会渲染两次，第二次把意图吃掉）；另外 `PF.tabs()` 的初始渲染是同步的，会被它同步读到的页面级 `let` 必须声明在 `PF.tabs()` 之前，否则撞 TDZ。

### 演示卫生
